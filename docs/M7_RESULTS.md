## Part 1 — Qwen Task 2 の失敗分類

Task 2 の保存済み生成文（`raw`）を、共通パーサ（`parse_prediction`、
`ANSWER: X` または末尾の単独文字 A–D を要求）で分類した。
出典: `results/m7/qwen_task2_taxonomy.csv`（pod 上）。

| 条件 | seed | 範囲外の文字 | 解釈できたが不正解 | 解釈できて正解 | 解釈できた回答中の正解率 |
|---|---|---|---|---|---|
| Qwen FT | 0 | 219 | 586 | 195 | 195/781 = 0.250 |
| Qwen FT | 1 | 220 | 591 | 189 | 189/780 = 0.242 |
| Qwen FT | 2 | 142 | 553 | 305 | 305/858 = 0.355 |
| Qwen ZS | 0 | 40 | 626 | 334 | 334/960 = 0.348 |

`no_letter` と `multiple_letters` は全条件・全 seed で 0 件だった。
範囲外の文字はスポットチェックで確認された "E" のような、
A–D 以外の単独文字である。

読み取り:

- **(a) 崩れの主因は「形式」だけではない。** FT の誤り 805 件（seed 0）の
  うち形式失敗は 219 件（27%）で、残り 586 件は解釈できたのに選んだ
  文字が違う。しかも解釈できた回答に限っても正解率は 0.250 で、
  4 択の偶然水準（0.25）そのもの。seed 1 も 0.242 と偶然水準。
  つまり Yes/No 形式のペアだけでの追加学習は、A–D 形式を壊した
  だけでなく、解釈可能な回答の中身からも選択の信号を消している。
- **(b) 文字の偏りはある。** FT の解釈済み予測分布（seed 0）は
  A 169 / B 157 / C 203 / D 252 で、D に偏る（解釈済みの 32%）。
  seed 1 も D 261・C 224 が多く A 139・B 156 が少ない。
  正解分布はほぼ均等（M1 監査）なので、これは予測側の偏り。
- **(c) seed 2 が違う理由。** seed 2 は形式失敗が 142 件まで減り
  （回答率 0.858）、解釈済みの正解率も 0.355 と偶然水準を上回る。
  予測分布も A 243 と A が戻るなど、他の seed と形が違う。
  記録の確認（`results/m7/qwen_training_artifacts.csv`）では、
  設定面の異常は見つからなかった。学習 manifest は seed ごとに
  ハッシュが異なる（設計どおり別データ）。adapter 設定は
  target_modules の並び順以外は 3 seed で同一（ハッシュ差はその
  並び順だけが原因）。評価の run_config は adapter のパス以外同一で、
  評価 seed は全て 13。つまり seed 2 の改善は設定差ではなく、
  学習データと学習 seed（13+seed）の違いによる通常のばらつきの
  範囲で起きている。
- **(d) zero-shot の失敗は質が違う。** ZS は形式失敗が 40 件（4%）しか
  なく、誤りの大半は「解釈できたが不正解」626 件。解釈済みの正解率は
  0.348 で偶然水準より上。予測は A 315 / B 427 と A・B に強く偏り、
  C 97 / D 121 が極端に少ない。FT の「形式崩壊＋中身も偶然水準」とは
  別種の失敗で、FT は ZS の弱点（選択の偏り）を引き継いだのではなく、
  別の壊れ方をしている。

### Task 1-dim のグループ別精度

公式 item には `group`（simple / complex、各 500 件）と
`meta.tier`（easy_neg 250 件 / hard_neg 250 件 / positive 500 件）が
ある。seed 0 の精度（他 seed も同傾向）:

| 条件 | simple | complex | easy_neg | hard_neg | positive |
|---|---|---|---|---|---|
| SigLIP 2 凍結 | 0.662 | 0.678 | 0.772 | 0.580 | 0.664 |
| EG2 凍結 | 0.652 | 0.676 | 0.700 | 0.624 | 0.666 |
| EG2 部分更新 | 0.748 | 0.772 | 0.768 | 0.684 | 0.794 |
| Qwen FT | 0.636 | 0.714 | **0.972** | **0.936** | **0.396** |
| Qwen ZS | 0.590 | 0.674 | 0.708 | 0.684 | 0.568 |

- 凍結系・部分更新では hard_neg が最も難しく、部分更新は全グループを
  底上げする（positive は 0.792〜0.808 まで改善）。
- **Qwen FT は非対称に壊れている**: 否定側（easy_neg 0.908〜0.972、
  hard_neg 0.852〜0.936）は ZS より大幅に良いのに、肯定側
  （positive）は seed 0 で 0.396 まで落ちる（seed 1/2 は 0.558/0.546）。
  Yes/No 学習で「No と答える」方向に強く寄った結果と読める。
  Task 1-dim の seed 間ばらつき（0.675/0.719/0.725）の主因は
  この positive 側のばらつき。

### SigLIP 2 Task 1-dim の seed 0 外れ値

seed 0 が誤った 330 件の内訳（seed 1/2 の正誤との対応）:

- seed 1・2 も誤る（共通の難問）: 120 件
- seed 1 だけ誤る: 45 件 / seed 2 だけ誤る: 27 件
- seed 1・2 は両方正解（seed 0 だけの誤り）: 138 件

seed 0 の誤りの 42% は他の seed が解ける問題で、少数の壊れた問題に
集中しているのではなく広く散っている。seed 0 の head が全体に
少し弱い、という形の外れ方。

### 学習曲線フォローアップ（10,000 → 20,000 ペア、凍結系）

curve セルの予測は保存されており（`results/m6/curves/`）、
10k セルと 20k セルの item 単位比較ができた。

- Task 2 の伸びは、10k 時点で head の上位 2 候補のスコア差
  （margin）が小さかった「迷っている問題」にほぼ集中する。
  低 margin 側の半分（500 件）では 直った 38〜50 件・壊れた
  16〜35 件、高 margin 側の半分では 直った 0〜5 件・壊れた
  0〜4 件しか動いていない。確信の持てている問題は 10k で
  すでに安定しており、追加データは境界付近を押し上げている。
- Task 1 は入れ替わりが激しい割に純増が小さい。SigLIP 2 は
  seed 0 で 直った 69・壊れた 84 と純減（曲線の 0.740 → 0.725 の
  下がりに対応）、seed 1/2 は +10/+17。EG2 は +6/+9/+4。
- Task 1-dim も同様で、純増は SigLIP 2 が −8/−1/+20、
  EG2 が −1/+8/+30 と seed でばらつく。

## Part 3 — 費用対性能の読み

出典: `results/m6/summary/main_table.csv`。ただし同表では部分更新と
Qwen FT の seed 0 の GPU 時間が空欄のため、自動集計
（`results/m7/cost_accuracy.csv`）は `incomplete_costs` を返した。
seed 0 の合計は M4/M5 の記録（docs/M6_RESULTS.md に転記済み:
部分更新 2.198 GPU-h、Qwen FT 3.222 GPU-h）を使うと、3 seed 平均は
部分更新 1.82 GPU-h、Qwen FT 4.38 GPU-h になる。補完なしの
seeds 1–2 のみの平均は部分更新 1.63 GPU-h、Qwen FT 4.96 GPU-h。

| 条件 | GPU-h（3 seed 平均） | Task 1 | Task 1-dim | Task 2 |
|---|---|---|---|---|
| SigLIP 2 凍結 | 0.354 | 0.727 | 0.693 | 0.880 |
| EmbeddingGemma 2 凍結 | 1.121 | 0.737 | 0.671 | 0.859 |
| EmbeddingGemma 2 部分更新 | 1.816 | **0.766** | **0.759** | **0.950** |
| Qwen3-VL 8B FT | 4.382 | 0.750 | 0.706 | 0.230 |
| Qwen3-VL 8B ZS（単一ラン） | 0.176 | 0.653 | 0.632 | 0.334 |

- **Task 1**: 最高精度 0.766（部分更新）から 0.01 以内に入るのは
  部分更新だけ。次点の Qwen FT（0.750）は 0.016 差で圏外。
  よって「最高の 0.01 以内で最も安い条件」= 部分更新（1.82 GPU-h）。
- **Task 2**: 最高精度 0.950（部分更新）から 0.01 以内も部分更新だけ。
  次点は SigLIP 2 凍結の 0.880 で 0.070 差。
- 予算優先なら SigLIP 2 凍結が別格に安い（0.354 GPU-h、部分更新の
  約 1/5）。精度の代償は Task 1 で −0.039、Task 2 で −0.070。
- Qwen FT は最も高コスト（4.38 GPU-h）で Task 2 が最下位。
  費用対性能では全タスクで割に合わない。

## 制限事項

- `main_table.csv` の seed 0 GPU 時間の空欄（部分更新・Qwen FT）により、
  表だけからの自動の費用集計は不完全になる。本書の平均は M4/M5 の
  記録で補った値で、その旨を明記した。
- `cumulative_cost.csv` の列名と中身の不整合（上記）。
- 重なり分析では ZS の参照ランを 3 seed 分に再利用している。
  独立した 3 回の実行ではない。
- 分類・重なりは保存済み予測フィールドのみに基づく。再推論はしていない。
