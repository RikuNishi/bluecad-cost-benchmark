# M3 結果：凍結特徴＋共通分類器（2026-11-07 実行）

実行環境：RunPod Secure Cloud、RTX 4090（24GB）、BF16。Pod 課金時間は
19:21–25:33（約6.2時間、$0.89/h で約 $5.5）。パイプライン自体は 22:14 に
完了していたが、Pod の終了確認が遅れ約3.3時間のアイドル課金が発生した。
次回は無人実行＋自動終了の仕組みを入れる。

## 条件（全モデル共通）

- 学習ペア：共通 manifest 20,000 ペア（正負 50/50、seed 0）
- 分類器：共通 head（[d, r, |d-r|, d*r] 連結＋標準化＋ロジスティック回帰）
- 閾値：検証ペア 2,000 件で精度最大化した値を使用（検証ラベル使用を明記）
- 採点：全問分母。回答率 1.0（全問に予測あり）
- 特徴抽出対象：36,366 画像（学習・検証・Task 1/1-dim/2 の和集合）

## 実測値（本研究の測定値。文献値とは別）

検証精度（閾値調整後／0.5固定）：SigLIP 2 = 0.7745／0.7730、
EmbeddingGemma 2 = 0.7610／0.7565。

| モデル | Task 1 Acc | Task 1 macro-F1 | Task 1-dim Acc | Task 2 Acc |
|---|---|---|---|---|
| SigLIP 2 (base-patch16-224, rev 75de2d5) | 0.725 | 0.721 | 0.670 | 0.872 |
| EmbeddingGemma 2 (rev f9972ac) | 0.740 | 0.739 | 0.664 | 0.853 |

Task 2 はペアスコアの argmax で予測。いずれも学習済み head の結果であり
zero-shot ではない。原論文の凍結エンコーダ数値は検索 Recall@1 であり、
タスクも指標も異なるため直接比較しない。原論文の VLM zero-shot の
Task 1 は 0.52–0.67 だが、head 学習の有無が違う別条件である。

## コスト実測（RTX 4090、results/costs.jsonl より）

| 工程 | SigLIP 2 | EmbeddingGemma 2 |
|---|---|---|
| 特徴抽出 36,366 画像 | 592 秒（0.165 GPU-h、最大 1.03 GB） | 1,820 秒（0.506 GPU-h、最大 6.44 GB） |
| head 学習 20,000 ペア | 1.2 秒 | 1.1 秒 |
| 評価 3,000 問（特徴キャッシュ） | 0.8 秒 | 0.7 秒 |

前提コストとして、データ取得は約90秒、シャード展開はネットワーク
ボリュームへの小ファイル書き込みが律速で約2時間（並列化で短縮）。
初回実行は revision 取得方法の不具合で両モデルとも失敗し、修正後に再実行した
（失敗した抽出の記録も costs.jsonl に残っている）。
